Reuse upstream `G1_29_ArmIK` and its Pinocchio/CasADi/IPOPT solver. Add only the
adapters and tests needed for motor-order conversion, target frames, measured
initialization, stale-input handling and bounded commands. Do not introduce a
second optimizer. Audit `solve_ik` ordering separately from `solve_tau`: the
existing gravity helper has explicit order conversion, which does not prove every
other method shares the same contract.

The feedforward baseline follows Unitree's reduced-model static RNEA approach at
the solved pose, with zero velocity/acceleration. It is not IMU-aware or full-body
dynamic compensation. A floating-base inverse-dynamics implementation is **not**
a prerequisite to this milestone. Validate tracking and loads empirically and
improve compensation only when evidence warrants it. Do not silently remove the
old stationary diagnostic's tilt/waist gates or apply that diagnostic's acceptance
results to walking; the new combined runtime needs separate limits and evidence.

Physical motion mode keeps stock locomotion active; do not call ReleaseMode or
start `run_g1_server.py`. Define arm ownership, waist behavior, blend-in/out and
command-loss handling explicitly. The reference initializes non-arm command fields
as well; do not assume firmware treats zero fields as equivalent. Slot 29.q is
the arm authority weight, not a physical joint. Verify actual firmware behavior.
Do not infer that normal release packets prove receipt, physical stopping, or
recovery from process/host failure.

## Controller Mapping

- Terminal `r`: start following; `q`: stop/exit. No implicit physical activation.
- Arm tracking is continuous after start, not squeeze-to-clutch. Match the
  reference's head-yaw-relative arm pose convention and waist-origin transform.
- Squeeze is reserved for BrainCo index flexion, not arm engagement.
- Trigger is reserved for the other BrainCo fingers with the reference's thumb
  coupling and saturation. For Dex1 it is gripper input. These are mappings, not
  authorization to instantiate a physical hand driver.
- Left stick: forward/backward and lateral velocity. Right stick X: yaw rate.
  Reference maps its WebXR stick values with minus signs and scale 0.3; explicitly
  convert Isaac Teleop/OpenXR axis conventions before applying this mapping.
- Right A: exit in the reference motion mode. Both stick clicks: damping request.
  Preserve stop priority; do not issue a nonzero Move after requesting damping.
- Reference terminal `s` toggles recording when enabled; do not claim recording
  support until connected to LeRobot's recording path.

The inspected reference calls `loco_wrapper.Damp()` while its wrapper declares
`Enter_Damp_Mode()`. Match the intended operator behavior, not that method-name
mismatch. Neither a damping request nor a headset button is an independent
physical emergency stop. Headset disconnection must not leave a held walking
command; require fresh input and an explicit restart after a fault.

`tests/robots/test_unitree_g1.py`, `tests/robots/test_unitree_g1_utils.py` and
`tests/teleoperators/test_unitree_g1_teleoperator.py`. No physical connection was
made. The software paths below are implemented on the new branch; manual headset,

[exact manual test plan](g1_vr_manual_test_plan), not the historical candidate's
commands. The runner deliberately lives in an example while hardware contracts
are being validated; it is not registered as an implicit default Robot backend.

Simulation uses the pinned Hub environment in-process without creating DDS. Dex3
fingers are constrained at zero to match the upstream IK inertias, not controlled.
The separate arm SDK diagnostic uses a supported pelvis/lower-body fixture;
free-base GR00T tests verify locomotion independently. Static gravity is evaluated
at the slew-limited target, using upstream Pinocchio RNEA. It is not measured-IMU
compensation. A physical payload mismatch must be reviewed before activation.

1. Freeze the new bugfix baseline and run its G1 robot/teleoperator tests.
2. Port the generic XR input/video adapters without embodiment/native-sim coupling.
   Test SDK field extraction, frame transforms, button polarity and invalid input.
3. Reuse upstream G1-29 IK with order/frame/failure tests and the Hub simulator.
   Verify arm pose tracking before adding locomotion.
4. Add joystick velocity mapping to GR00T in free-base G1-29 simulation. Test zero,
   forward/backward, lateral and turn commands, then combined arm/base motion.
   Reject G1-23 or incompatible controller selection rather than silently falling
   back. SONIC's token-only decoder is not a velocity adapter and is deferred.
5. Port camera-only, read-only feedback and shadow diagnostics. Shadow logs arm,
   hand and base intent without constructing command publishers or motion RPCs.
6. Port the reviewed arm-authority and bounded hold/joint tests without importing
   the previous generic IK. Preserve report provenance and explicit hardware gates.
7. Enable supervised physical VR arms while stationary after operator acceptance.
8. Add reviewed physical high-level velocity dispatch; validate locomotion alone,
   then combined arms/walking. Keep stock control and use explicit timeout/stop
   semantics, return-code checks and orderly handover. Do not auto-run hardware.
