# G1-29 VR: Manual Validation

Use the [standard CLI guide](g1_vr_standard_cli) for `lerobot-teleoperate`.
The standalone examples below provide individual validation procedures for
simulation, camera delivery, feedback, and bounded hardware motion.
G1-23, hand actuation, SONIC, and dataset recording are outside this workflow.

Run the following sequence on the G1's onboard PC2. Simulation does not initialize
DDS, even on PC2. Physical modes explicitly subscribe to the selected interface.
Do **not** run `run_g1_server.py`, MotionSwitcher/ReleaseMode, another arm publisher,
or another locomotion application alongside these examples.

## Environment

```bash
cd /path/to/lerobot
conda activate lerobot-dev
export PYTHONPATH="$PWD/src" PYTHONNOUSERSITE=1
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MUJOCO_GL=egl
python -c 'import lerobot; print(lerobot.__file__)'
```

The printed path must be this checkout's `src/lerobot`. The examples reject an
import from another checkout. Do not switch branches while a test is running.

Use the existing matching environment, or install LeRobot's `unitree_g1`, `test`
and `dev` extras, the Unitree SDK, and Hub simulation dependencies as described in
[the G1 guide](unitree_g1). Install Pinocchio **from conda-forge**, including its
CasADi bindings, not pip `pin`. Follow [Isaac Teleop installation](isaac_teleop) for the CloudXR extras,
GPU/driver and network prerequisites. On PC2, use the platform environment
setup before starting these examples; see the Orin video settings in the
[standard CLI guide](g1_vr_standard_cli).


Prepare pinned public assets, then disable downloads during testing:

```bash
export ASSETS="$(python examples/unitree_g1/prepare_vr_assets.py)"
export URDF="$ASSETS/assets/g1_body29_hand14.urdf"
export HF_HUB_OFFLINE=1
export CHANNEL=/tmp/lerobot-g1-vr-camera.rgb
export CLOUDXR_CONFIG="$PWD/examples/unitree_g1/cloudxr_quest3.env"
python examples/unitree_g1/validate_arm_sdk.py --urdf "$URDF" --write-template arm-contract.json
```

The downloader pins Hub simulator `68459ed68f6f68e1f661091dfcb6ebce44681aec` and
GR00T `7bb8a672f5a4213c9261ea5ac1f3f034f5078638`. Preserve the snapshot path, not
the symlink-resolved URDF blob path: meshes live relative to the snapshot.
Reports/templates refuse overwrites; choose new filenames for repeat runs.
Run the environment exports in every terminal.

## 1. Simulation Only

First, terminal-only synthetic input, no XR or physical DDS:

```bash
python examples/unitree_g1/run_vr_teleop.py --assets "$ASSETS" \
  --input synthetic --synthetic-velocity 0.1 0 0 --duration-s 8 \
  --output sim-synthetic-001.jsonl
```

Expect changing arm targets/measured positions, advancing base position, and a
`completed` report. Inspect for `ik_pause` or `invalid` events: process completion
alone does not prove tracking passed. Test GR00T axes and camera pixels with:

```bash
G1_VR_ASSETS="$ASSETS" python -m pytest -q \
  tests/robots/test_unitree_g1_vr_simulation.py \
  tests/integration/test_unitree_g1_vr_runner.py
```

Next, live headset with simulated camera. Review the NVIDIA EULA before passing
its acceptance flag:

```bash
python examples/unitree_g1/run_vr_teleop.py --assets "$ASSETS" \
  --video --channel "$CHANNEL" --duration-s 300 --output sim-vr-001.jsonl \
  --cloudxr-config "$CLOUDXR_CONFIG" --accept-cloudxr-eula
```

Connect the headset at `https://nvidia.github.io/IsaacTeleop/client` using PC2's IP;
accept its certificate at `https://HOST:48322` if required. One runtime/XR app at a
time. The script owns teardown: stop XR before CloudXR. Available GPU memory and
CUDA/Vulkan support are required; CPU physics success does not verify CloudXR.

Optional desktop view: add `--onscreen`. For viewer-only use `MUJOCO_GL=glfw` and
omit `--video`; this can run through `ssh -Y`, subject to the client's GLX support.
SSH forwarding does not carry headset video. For combined viewer/video use local
display with `MUJOCO_GL=egl`; remote GLX support varies. Validate desktop and headset viewing separately.

### Controls and Observations

- `r` then Enter: start/resume continuous tracking. `p` then Enter: pause, hold
  measured arms and send zero base intent. `q` then Enter or right A: exit.
- Move/rotate each controller: corresponding wrist pose in a head-yaw-relative
  frame, with Unitree's head-to-waist offset. This is absolute pose mapping, **not
  a no-jump clutch**. Match the starting posture and inspect targets in shadow.
- Squeeze/trigger: log future hand intent only; neither engages the arms.
- Left stick forward/back and left/right: base velocity. Right stick X: yaw.
  OpenXR +Y means forward; maximum simulation components are 0.3 m/s or rad/s.
- Both stick clicks: stop/damping request. In simulation this drops joint stiffness
  for the final step. In activated physical walk/combined modes it requests stock
  damping after zero velocity. In arms/shadow modes no locomotion RPC exists:
  this stops/releases the session, **not a stock damping command**.
- Tracking loss/stale input or failed IK pauses tracking and zeros base intent;
  explicit `r` is needed after recovery. Exit/restart after transport/watchdog fault.

Verify arms separately with sticks centered, base axes separately with hands still,
then combined motion. Check correspondence, direction, smoothness and latency.
Upstream IK has no self-collision constraint. In long synthetic runs its log-rotation
residual can hit a numerical failure; the runner pauses rather than forwarding
the failed solution. Such an event is not a tracking acceptance pass.

## 2. Physical Feedback Only

Verify the robot identity, firmware, network interface and stock mode with the
responsible operator. Set only `arm_sdk.network_interface` initially; leave review
flags false. This command cannot create a command publisher or locomotion client:

```bash
python examples/unitree_g1/validate_arm_sdk.py --backend hardware --phase read-only \
  --contract arm-contract.json --output physical-feedback-001.json
```

Expect progressing ticks, fresh feedback, correct arm joint identity/positions and
unchanged physical behavior. Record the mode bytes; they are not evidence of an
approved high-level mode or of exclusive command ownership.

## 3. Physical Camera in Headset

Verify an actual supported camera device and resolution first. Terminal A:

```bash
python examples/unitree_g1/validate_xr_readonly.py camera --device /dev/video4 \
  --channel "$CHANNEL" --duration-s 300 --output camera-001.jsonl
```

Replace `/dev/video4` with the verified device. Terminal B:

```bash
python examples/unitree_g1/validate_xr_readonly.py display --channel "$CHANNEL" \
  --duration-s 120 --output display-001.jsonl \
  --cloudxr-config "$CLOUDXR_CONFIG" --accept-cloudxr-eula
```

Expect the actual camera's live, correctly oriented/color image. Stop its producer:
expect a stale/unavailable placeholder, not a frozen image labeled live. Restart
the producer with a new report: expect recovery. This is a mono display, not stereo
or head-driven camera control. Capture timestamps are read-start times, not sensor
exposure timestamps. Neither process creates motor publishers.

## 4. Physical XR Shadow

Stop the display, keep the camera producer if using video, then:

```bash
python examples/unitree_g1/run_vr_teleop.py --mode shadow --assets "$ASSETS" \
  --contract arm-contract.json --video --channel "$CHANNEL" \
  --duration-s 120 --output shadow-001.jsonl \
  --cloudxr-config "$CLOUDXR_CONFIG" --accept-cloudxr-eula
```

Press `r` after tracking is valid. Move one controller at a time and test all stick
axes. Proposed targets/velocities must change while `motor_publication` and
`base_rpc` stay false. The robot must not follow. Pause/loss must hold proposed
measured pose and zero proposed velocity. Inspect reachable start posture, joint
identity, signs and proposed displacement against the intended physical envelope.

## 5. Supervised Hold

Stop read-only XR. Complete the contract with the responsible operator; do not
mechanically approve flags. Review firmware-supported `rt/arm_sdk` ownership,
stock lower-body owner, zero/uncommanded waist fields, expected mode, payload,
gains/limits, weight-zero handover, packet loss and process/host-death response.
Provide independent physical stop and support arrangements. The local lock cannot
detect competing publishers on another host or in another application.

```bash
python examples/unitree_g1/validate_arm_sdk.py --backend hardware --phase hold \
  --enable-motion --contract arm-contract.json --urdf "$URDF" \
  --output physical-hold-001.json
```

This applies torque even without a displacement request. Observe both arms,
unchanged stock waist/leg ownership, no oscillation, and actual handover on exit.
Normal/fault close attempts weight-zero release; receipt and physical stopping
are not proven. The Python watchdog cannot act after process death or a blocked
native SDK call. Stop on any discrepancy; do not wear the headset for this stage.

## 6. Bounded Single Joint

Only after hold acceptance, choose operator-approved signed excursion and duration:

```bash
python examples/unitree_g1/validate_arm_sdk.py --backend hardware --phase joint \
  --enable-motion --contract arm-contract.json --urdf "$URDF" \
  --joint kLeftElbow.q --delta-rad "$REVIEWED_DELTA_RAD" \
  --duration-s "$REVIEWED_DURATION_S" --output physical-left-001.json
```

Expect the selected joint to move out and return, correct sign/extent and no
unexpected other-joint motion. Inspect the report and physical handover before
repeating with `kRightElbow.q` and a new filename. The automated arm fixture locks
pelvis/lower joints with model constraints; it verifies the arm command/backend
path, not stock balance or firmware blend behavior. Physical limits are unchanged.
Simulation timing does not establish hardware feedback or watchdog timing.

## 7. Stationary Physical VR Arms

After shadow and bounded-motion acceptance, review `vr_pose_mapping_reviewed` and
the per-session displacement envelope. The default 0.05 rad envelope is deliberately
small; this is bounded supervised validation, not unrestricted teleoperation.

```bash
python examples/unitree_g1/run_vr_teleop.py --mode arms --enable-motion \
  --assets "$ASSETS" --contract arm-contract.json --duration-s 60 \
  --output physical-vr-arms-001.jsonl \
  --cloudxr-config "$CLOUDXR_CONFIG" --accept-cloudxr-eula
```

No activation until fresh tracking plus `r`. Begin still, then small movements of
one arm at a time. Stock balance remains external. Add the previously accepted
`--video --channel "$CHANNEL"` path if needed. Sticks never issue base RPCs here.

## 8. Walking, Then Combined

Separately review `locomotion_reviewed`, `damping_reviewed`,
`combined_ownership_reviewed`, `base_limits` and the actual stop procedure.
`SetVelocity` is the SDK operation underneath Move; this code checks its return
code and sends bounded-duration commands. Firmware timeout behavior still needs
independent verification. Damping can remove balance support; verify its use.

```bash
python examples/unitree_g1/run_vr_teleop.py --mode walk --enable-motion --enable-locomotion \
  --assets "$ASSETS" --contract arm-contract.json --duration-s 60 \
  --output physical-walk-001.jsonl \
  --cloudxr-config "$CLOUDXR_CONFIG" --accept-cloudxr-eula
```

Walk mode subscribes to arm feedback but never acquires arm authority. Test tiny
axis commands, centering, pause and the independent stop arrangement under
supervision. After acceptance, repeat with `--mode combined` and a new report.
The reduced static gravity model is not IMU-aware; its upright/waist gate is still
active. Do not relax it merely to pass walking. Unmodeled tools/hand masses need
review: the simulation uses locked Dex3 joints to match upstream IK's hand inertias.
Finger actuators receive zero commands; no hand driver is enabled. A bare wrist or
BrainCo-equipped physical robot is a different payload, not automatically a matching
gravity model. No collision avoidance is provided.

## Automated Regression

Run the focused software checks with the prepared assets:

```bash
G1_VR_ASSETS="$ASSETS" python -m pytest -q \
  tests/robots/test_unitree_g1.py tests/robots/test_unitree_g1_utils.py \
  tests/robots/test_unitree_g1_arm_sdk.py tests/robots/test_unitree_g1_vr_control.py \
  tests/robots/test_unitree_g1_vr_simulation.py tests/integration \
  tests/teleoperators/test_unitree_g1_teleoperator.py \
  tests/teleoperators/test_unitree_g1_vr_input.py \
  tests/teleoperators/test_unitree_g1_xr_video.py
```

Automated suites cover SDK packets/authority/watchdogs, read-only boundaries,
mapping and installed XR schema, camera freshness/recovery, real headless physics,
GR00T directions and supported-arm hold/joint tests. GPU headset delivery, X viewing,
PC2 installation and physical stages require operator validation. `completed` or
`software_checks_passed` never means hardware acceptance; reports retain
`pending_operator_review`. Preserve reports and the exact source revision for review.
