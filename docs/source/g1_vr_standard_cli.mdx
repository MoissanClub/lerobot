# G1 VR Through Standard LeRobot Teleoperation

The `xr_controllers` teleoperator reads headset and controller input. A saved
action processor maps poses through G1-29 inverse kinematics, and the
`unitree_g1_motion` robot handles simulation or gated physical transports.
This uses the standard `lerobot-teleoperate` loop and is separate from the
`unitree_g1` whole-body server workflow.

Simulation uses MuJoCo and GR00T for lower-body control. Physical arm commands
use `rt/arm_sdk` while the stock Unitree controller owns balance and locomotion.
Arm feedforward uses reduced-model static gravity compensation, not IMU-aware
full-body dynamics; review the actual hand/tool payload before motion.

## Offline Replay

From this checkout with its dependencies installed and editable import pointing
here (not another LeRobot worktree):

```bash
python examples/unitree_g1/prepare_vr_assets.py \
  --config-dir /tmp/g1-cli-replay --replay-frames 100
MUJOCO_GL=egl lerobot-teleoperate --config_path=/tmp/g1-cli-replay/teleoperate.json
```

Uses pinned HF assets and policies, actual IK and MuJoCo/GR00T. Replay closes
automatically; `report.jsonl` contains measured positions and command targets.
Use a new output directory for another run: reports refuse overwrite.
No headset, DDS publisher or physical robot is used. Replay is explicitly marked
non-live and cannot activate the physical Robot.

## Live Simulation

```bash
python examples/unitree_g1/prepare_vr_assets.py --config-dir /tmp/g1-cli-live
MUJOCO_GL=egl lerobot-teleoperate \
  --config_path=/tmp/g1-cli-live/teleoperate.json \
  --teleop.cloudxr_config=examples/unitree_g1/cloudxr_quest3.env \
  --teleop.accept_cloudxr_eula=true \
  --teleop.video_channel=/tmp/g1-cli-camera \
  --robot.video_channel=/tmp/g1-cli-camera
```

Connect the headset through the Isaac Teleop client. In the command terminal,
`r` + Enter starts tracking, `p` + Enter pauses, `q` + Enter exits. Tracking loss
pauses and requires another explicit start. Mapping remains Unitree-style:
head-relative wrists without squeeze clutches, left stick translation, right
stick yaw; controller stop buttons remain active. Hands are locked, not actuated.

For a local MuJoCo window add `--robot.onscreen=true` with a working local display.
On Jetson Orin with Isaac Teleop 1.4.145, add
`--teleop.video_openxr_composition=false` when using headset video. Native OpenXR
quad composition can show a black panel on this runtime; this option asks Televiz
to render the panel into its shared render target instead. Platform detection and
the EGL preload belong in the PC2 launcher, not the generic XR teleoperator.
Headless physics success does not establish X forwarding or headset compatibility.
CloudXR is started only when configured with explicit EULA acceptance; otherwise
an externally owned runtime is expected. Cleanup closes Robot before XR, then
XR before an owned CloudXR runtime.

## Physical Hardware

Follow the [manual validation procedure](g1_vr_manual_test_plan) for simulation,
read-only hardware, camera/headset, bounded motion, and combined motion.

The Robot supports `mode=shadow|arms|walk|combined`, requires a reviewed contract
and a new report path for hardware, and explicit `enable_motion=true` for motion.
Walking additionally requires `enable_locomotion=true`. Physical camera frames
come from the separate read-only producer; select
`teleop.video_source=g1-29-physical-camera`, not a Robot simulation video channel.
Do not run the whole-body `run_g1_server.py` alongside stock-owned arm control.

## Physical Camera in VR

Discover cameras using the standard [camera workflow](cameras):

```bash
lerobot-find-cameras opencv
```

Inspect the saved images and choose the RGB camera identifier. Use
`lerobot-find-cameras realsense` for native RealSense discovery. A RealSense device
can expose several OpenCV nodes; a depth/infrared node is not the RGB camera.
Device indices may change after reconnecting or rebooting.

Camera-only mode uses the same `robot.cameras` configuration and camera factory
as other LeRobot Robots. On PC2, load the platform environment first:

```bash
python_bin="$HOME/miniforge3/envs/lerobot-dev/bin/python"
lerobot_dir="$HOME/lerobot"
source "$HOME/unitree_g1_dev/pc2/IsaacTeleop/lerobot_env.sh"
lerobot_environment
cd "$lerobot_dir"
```

Stop other camera and CloudXR sessions. Replace index `4` below with the identifier
verified by discovery. Review the NVIDIA EULA before supplying its acceptance flag.
Use a fresh channel directory for each session:

```bash
camera_run=$(mktemp -d /tmp/g1-camera-XXXXXXXX)
lerobot-teleoperate \
  --robot.type=unitree_g1_motion \
  --robot.mode=camera \
  --robot.cameras='{"head": {"type": "opencv", "index_or_path": 4, "width": 640, "height": 480, "fps": 30}}' \
  --robot.video_channel="$camera_run/camera.rgb" \
  --robot.report_path="$camera_run/report.jsonl" \
  --teleop.type=xr_controllers \
  --teleop.terminal_control=true \
  --teleop.video_channel="$camera_run/camera.rgb" \
  --teleop.video_source=g1-29-physical-camera \
  --teleop.video_openxr_composition=false \
  --teleop.cloudxr_config=examples/unitree_g1/cloudxr_quest3.env \
  --teleop.accept_cloudxr_eula=true \
  --fps=30
```

The composition setting above is for Orin. Camera mode opens one RGB camera and
publishes to the selected XR channel. It does not load simulation/IK assets,
subscribe to joint feedback, or create a motor publisher or locomotion client.
VR poses, triggers, sticks, and `r` do not command motion in this mode. Do not
supply a motion action processor. `q` then Enter or Ctrl+C exits.

On the headset, open `https://<PC2-WIFI-IP>:48322`, accept the certificate, and
use the client button supplied by the PC2 installer. Select H.264, Connect, then
Play. The image appears without pressing `r`. Check the actual scene, color,
orientation, and responsiveness. A camera read timeout stops frame publication;
the headset replaces old frames with an unavailable placeholder. Fresh capture
resumes display. Device removal may require restarting the session.

Capture timestamps are conservative host-side bounds between successive frame
reads, not sensor exposure timestamps. This is a mono RGB panel, not stereo/depth
rendering. Use `--teleop_time_s=600` for a bounded review; by default it runs until
stopped. The report records frame publication, which does not establish that a
person saw the image in the headset.

For a command generated from the shared PC2 hardware profile:

```bash
bash ~/unitree_g1_dev/pc2/IsaacTeleop/run_lerobot_camera.sh --accept-eula
```

Add `--prepare-only` to print the generated configuration and direct
`lerobot-teleoperate` command without opening devices. Source the PC2 environment
as above before running that command in another terminal.
